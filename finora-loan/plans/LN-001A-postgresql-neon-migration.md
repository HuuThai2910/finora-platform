# LN-001A — PostgreSQL 17 và Neon cho Loan Service

## Bản đọc nhanh theo nghiệp vụ

### Chức năng này giải quyết việc gì?

LN-001A chuyển nơi lưu dữ liệu của Loan từ MySQL sang PostgreSQL 17. Khi làm việc hằng ngày, Thái dùng Neon để không phải bật Docker database; khi mất mạng hoặc chạy test tự động, có PostgreSQL Docker/Testcontainers cùng phiên bản làm phương án thay thế.

### Ai sử dụng và nhìn thấy gì?

- Thái chọn profile/cấu hình kết nối rồi chạy Loan; không phải thay code nghiệp vụ.
- Borrower/admin không thấy khác biệt trên UI hoặc API.
- Loan chỉ kết nối project `finora-loan`; Payment, Blockchain và Fineract có database/credential riêng nên một database lỗi không kéo sập toàn bộ dữ liệu microservice.

### Dữ liệu cấu hình quan trọng

| Dữ liệu | Người vận hành hiểu là gì | Ảnh hưởng |
|---|---|---|
| `LOAN_DB_URL` | Địa chỉ đúng database Loan | Sai địa chỉ thì Loan không khởi động; tuyệt đối không trỏ sang database service khác |
| `LOAN_DB_USERNAME/PASSWORD` | Quyền đăng nhập database | Chỉ lấy từ Neon Connect hoặc local secret, không commit Git |
| Flyway version | Lịch sử thay đổi schema | Bảo đảm mọi môi trường tạo bảng giống nhau |
| Hibernate `validate` | Chế độ chỉ kiểm tra | Code và schema lệch nhau thì dừng, không tự tạo/sửa bảng |

### Luồng, lỗi và ví dụ

```text
Chọn Neon hoặc local PostgreSQL → kết nối → Flyway chạy migration → Hibernate validate → Loan sẵn sàng
```

Ví dụ: Neon tạm ngủ hoặc mất mạng thì Loan báo không sẵn sàng; lập trình viên có thể bật `loan-postgres` local và đổi datasource, không sao chép dữ liệu sang DB của service khác. Task hoàn tất khi compile/test PostgreSQL pass, Neon kết nối được bằng secret ngoài Git và database sạch chạy migration cuối thành công.

## 1. Lý do thay đổi

Thái quyết định Loan, Payment và Blockchain dùng PostgreSQL; mỗi service có Neon Project riêng. Mục tiêu:

- thống nhất engine cho các service Thái và Apache Fineract nhưng vẫn tách database/credential;
- tận dụng Neon cho môi trường hằng ngày mà không cần bật database Docker;
- giữ PostgreSQL Docker/Testcontainers để làm việc offline và test deterministic;
- tránh tiếp tục đầu tư vào MySQL migration/config khi code Loan còn ở giai đoạn đầu.

LN-001 đã được nghiệm thu theo MySQL ngày 2026-08-01 và được giữ làm lịch sử. Hướng runtime MySQL của LN-001 bị task này thay thế.

## 2. Phạm vi

- Đổi Loan JDBC driver từ MySQL Connector/J sang PostgreSQL JDBC.
- Bỏ `flyway-mysql`; PostgreSQL được Flyway core của Spring Boot 3.2 quản lý.
- Đổi datasource mặc định sang PostgreSQL offline tại `localhost:15433`.
- Không chạy V1/V2 thử nghiệm; V1/V2 cuối được viết sau khi LN-003/LN-004 được duyệt.
- Đổi integration test từ MySQL 8.4 sang PostgreSQL 17 Testcontainer.
- Đổi Loan Docker fallback thành `loan-postgres` và non-superuser runtime role.
- Cập nhật Design, PLAN, registry, roadmap, Postman và hướng dẫn Neon.

Ngoài phạm vi:

- Không tự tạo Neon Project bằng API vì đây là external state/credential do Thái sở hữu.
- Không chuyển User/Keycloak của Hải khỏi MySQL.
- Không nhập dữ liệu MySQL cũ nếu chưa xác định dữ liệu cần giữ.
- Không tự chốt nghiệp vụ Product/Application; LN-003/LN-004 là nguồn thiết kế mới nhất và phải được duyệt trước khi viết V1/V2 cuối.

## 3. Quyết định database

| Thành phần | Quyết định |
|---|---|
| Engine | PostgreSQL 17 |
| Managed development | Neon Project `finora-loan`, database `neondb`, default role lấy từ Connect |
| Offline fallback | Docker `postgres:17.5-alpine`, host port `15433` |
| Migration | Flyway, `ddl-auto: validate`; chưa có migration nghiệp vụ được phép chạy |
| Integration test | PostgreSQL 17 Testcontainers, không dùng Neon/mạng công cộng |
| Thời gian | `TIMESTAMP(6) WITH TIME ZONE` ánh xạ Java `Instant` |
| ID | `BIGINT GENERATED BY DEFAULT AS IDENTITY` |
| Enum | `VARCHAR + CHECK`, không native PostgreSQL enum |
| Tiền | `DECIMAL(18,2)`/`BigDecimal` |

Neon và Fineract cùng dùng PostgreSQL nhưng không dùng chung Project, database, role, schema hoặc migration.

## 4. Chiến lược migration

V1/V2 thử nghiệm chưa được Git merge và chưa chạy trên Neon dùng chung. Do entity/nghiệp vụ Product/Application đang được thiết kế lại, hai migration này được tháo khỏi Flyway thay vì chuyển nguyên schema sai sang PostgreSQL.

Khi LN-003/LN-004 được duyệt, V1/V2 cuối phải tuân theo PostgreSQL:

- `AUTO_INCREMENT` → `GENERATED BY DEFAULT AS IDENTITY`;
- `SMALLINT UNSIGNED` → `SMALLINT` + `CHECK >= 0` phù hợp;
- `DATETIME(6)` → `TIMESTAMP(6) WITH TIME ZONE`;
- bỏ `ENGINE=InnoDB`;
- query metadata test dùng `current_schema()` thay `DATABASE()`.

Nếu phát hiện V1/V2 thử nghiệm đã xuất hiện ở một database cần giữ dữ liệu thì không được viết đè checksum. Khi đó phải tạo database sạch hoặc lập migration/công cụ chuyển riêng. Với Neon mới của Thái, giữ `neondb` chưa có bảng nghiệp vụ cho tới khi V1/V2 cuối được duyệt.

## 5. Dữ liệu MySQL cũ

- Không xóa volume `docker_loan-mysql-data` tự động.
- Dữ liệu Postman/test được tạo lại trên PostgreSQL.
- Nếu Thái xác nhận có dữ liệu cần giữ, phải export logic, mapping kiểu và import có kiểm tra; không copy MySQL data directory.
- Sau khi PostgreSQL được nghiệm thu và dữ liệu cũ không cần nữa, Thái mới quyết định xóa volume cũ.

## 6. Cấu hình runtime

Local Docker mặc định:

```text
LOAN_DB_URL=jdbc:postgresql://localhost:15433/finora_loan
LOAN_DB_USERNAME=finora_loan
LOAN_DB_PASSWORD=<local secret>
```

Neon:

```text
LOAN_DB_URL=jdbc:postgresql://<neon-host>/neondb?sslmode=require
LOAN_DB_USERNAME=<default role từ Neon Connect>
LOAN_DB_PASSWORD=<Neon secret>
```

Không commit URL chứa password. Dùng direct endpoint trước; pool/tuning chỉ thay đổi sau khi đo.

## 9. Failure path

- Neon unavailable: readiness DOWN; không tự chuyển sang database local âm thầm.
- SSL/credential sai: fail startup rõ, không log password/connection string đầy đủ.
- Free quota gần 0,5 GB: đo `pg_database_size`, dọn dữ liệu test/branch hoặc nâng gói; không chia một Loan DB qua nhiều Project.
- Docker daemon không chạy: unit test vẫn chạy; integration Testcontainers được báo blocker, không thay bằng H2.
- Flyway checksum khác trên database đã migrate: dừng, kiểm tra environment; không dùng `repair` để che migration bị sửa ngoài kế hoạch.
